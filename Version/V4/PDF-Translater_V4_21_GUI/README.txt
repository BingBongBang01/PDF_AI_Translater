PDF Translater GUI

V4.2.1
1. 세로쓰기 "1줄이 2줄로" 문제 — 원인 확정
표 감지 로직이 "줄마다 시작 x가 다르면 표"라고 판단하는데, 세로쓰기 문서는 원래 여러 세로줄(컬럼)이 서로 다른 x0를 가지는 게 정상이다(오른쪽에서 왼쪽으로 읽는 컬럼들). 이걸 표로 오인해서 IPv4 주소는 통신 상대를 식별합니다가 IPv4/주소는/통신/... 처럼 낱개로 쪼개졌고, 각 조각이 원래의 좁은 컬럼 bbox에 억지로 맞춰지며 극단 축소된 것이다. 세로쓰기일 때는 판정 기준을 x0가 아니라 y-range 겹침 비율로 바꿔서(같은 문단의 컬럼들은 세로 범위가 겹치고, 표의 다른 행은 안 겹침) 고쳤다. 표/가로쓰기 문서 회귀 확인 완료.
2. PDF 압축 (기본 체크됨)
저장 로직 자체(증분저장/pypdf 폴백)는 안전성 때문에 그대로 두고, 저장 완료 후 별도로 재압축본(_compressed 접미사)을 만드는 후처리 단계를 추가했다. 실제 테스트에서 20.7MB → 36KB까지 줄어드는 걸 확인했다(pypdf 폴백 저장이 만드는 중복 리소스가 용량 문제의 핵심 원인이었음). GUI에 체크박스 추가(기본 체크).
3. 폴더 열기 / 결과 파일 자동 열기
"찾기" 옆에 폴더 열기 버튼(탐색기에서 파일 선택 상태로 열림), 하단에 결과 PDF 열기 버튼, 그리고 완료 시 자동 열기 체크박스(기본 체크)를 추가했다. 엔진이 [최종파일] 경로 마커를 출력하고 GUI가 이를 파싱한다.
4. Python 설치 문제 — 원인 확정

winget install에 소스를 명시 안 해서 마이크로소프트 스토어 버전과 겹칠 위험이 있었다 → --source winget 명시로 해결
winget 자체가 없는 컴퓨터에서는 자동 설치가 전혀 안 됐던 게 진짜 원인 → winget이 없거나 실패하면 python.org 공식 설치 프로그램을 직접 다운로드해서 무인 설치(PrependPath=1로 PATH 자동 등록)하도록 변경. 스토어를 아예 거치지 않는다.
조사 중 중요한 사실 발견: 3.12.11부터는 소스 전용 릴리스라 Windows exe 자체가 없다 — 반드시 3.12.10(바이너리 제공 마지막 버전)을 써야 해서 그 버전으로 고정했다.
혹시 이미 스토어판이 깔려있는 경우를 위해 "설정 > 앱 실행 별칭에서 python.exe 끄기" 안내도 추가.

V4.2.0
1. (버그수정, 심각) GPU 체크박스를 켜도 실제로는 NPU가 도는 문제 수정. 원인:
   Lemonade에서 NPU/GPU는 실행 시점 옵션이 아니라 모델 자체에 고정된 속성(recipe)
   이다 - "-FLM" 접미사 모델은 항상 NPU 전용, 그 외(-GGUF 등)라야 GPU를 쓴다.
   기존엔 장치와 무관하게 NPU 전용 모델(gemma4-it-e2b-FLM)만 로드해서 GPU 체크가
   무시됐다. 이제 NPU/GPU 각각 전용 모델 콤보박스로 분리했고(--model-local-npu/
   --model-local-gpu), 체크 안 된 장치의 콤보박스는 비활성화해 실수를 방지한다.
2. OCR 지원 추가: 텍스트 레이어가 거의 없고 이미지가 있는 페이지(스캔본)를 자동
   감지해 Tesseract OCR로 텍스트를 추출한 뒤 번역한다. 원본 이미지는 그대로 보존
   되고 그 위에 번역문만 얹힌다. 사용하려면 시스템에 Tesseract가 설치돼 있어야
   한다(https://github.com/tesseract-ocr/tesseract) - 없으면 안내 메시지만 뜨고
   해당 페이지는 원문 없이 넘어간다.
3. 세로쓰기(일본어 종서 등) 지원 추가: 텍스트 방향을 자동 감지해 세로로 긴 영역에
   맞춰 회전 배치한다. 완벽한 세로 조판(글자가 위→아래로 쌓이는 방식)은 아니고
   블록을 90도 회전시켜 배치하는 근사 방식이다.

3. build_exe.bat이 하드코딩된 버전(v3.82) 대신 translate_pdf.py의 버전을
   자동으로 읽어 EXE 파일명을 결정한다 (_get_version.py 헬퍼 사용).

V3.82
0. EXE 빌드 방식을 --onedir에서 --onefile로 변경 (build_exe.bat).
   빌드하면 dist\PDF-Translater-v3.82.exe 파일 '하나'만 생성되며, 이 파일만
   실행하면 콘솔 창 없이 GUI 하나만 뜬다 (--windowed 유지). 배포도 이 exe
   파일 하나만 복사하면 된다. 내부적으로 서브프로세스를 부르는 모든 지점
   (Python 3.12 탐색, pip 설치 등)에 콘솔 억제 플래그(CREATE_NO_WINDOW)를
   빠짐없이 적용해, 어떤 경우에도 별도 터미널 창이 뜨지 않도록 했다.
   실행은 반드시 dist\PDF-Translater-v3.82.exe를 직접 더블클릭할 것 -
   run_gui.bat/PDF-Translater_GUI.cmd로 실행하면 그 배치파일 자체가 cmd
   콘솔을 열어버리므로(이건 EXE와 무관, 배치파일의 특성) 개발/디버그용으로만 쓸 것.
1. (버그수정, 심각) 텍스트 정규화 정규식의 이중 이스케이프 오류로 소문자 't'가
   전부 공백으로 사라지던 문제 수정 (예: "Description"->"Descrip ion"). 원인:
   re.sub(r"[ \\t]+", ...) 의 raw string 안 '\\t'가 탭이 아니라 '\'와 't' 두
   글자로 해석되어 문자 클래스가 "공백 또는 t"가 되어버렸음 -> r"[ \t]+"로 수정.
2. (버그수정, 심각) 표/다단 레이아웃이 번역 후 깨지던 문제 수정. 원인: PDF에서
   서로 다른 셀/컬럼의 텍스트가 pymupdf에 의해 하나의 큰 텍스트 블록으로 묶여
   추출되는 경우가 있는데, 이를 통째로 한 세그먼트로 합쳐 번역·삽입하다 보니
   칸이 비거나 내용이 뒤섞였음. 이제 블록 안 줄들의 왼쪽 시작 x좌표가 들쭉날쭉하면
   (표/다단으로 판단) 줄 단위로 쪼개 각자 원래 위치에 개별 번역·배치한다.
   일반 문단(줄마다 왼쪽 정렬이 동일)은 지금처럼 하나로 합쳐 번역 품질을 유지한다.
